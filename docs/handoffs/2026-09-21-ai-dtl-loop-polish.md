## 修复与证据

### 1. 转写阶段不再启动多余模型回复

原实现收到 `input_audio_buffer.committed` 后立即 `response.create`，内部要求模型说“收到”，随后才等原生转写完成。真实长句出现 `response.done` 已结束、原生 ASR 仅有 delta 的情形；加长等待至 10 秒仍未治好。

事件顺序探针延后生成请求，观察到完整 ASR 在 commit 后约 264 ms 到达、早于生成请求。这支持“过早生成与转写存在竞态”的解释。最终实现内部 ASR 不发送 `response.create`，仅接收与 commit item 匹配的 completed。零散 delta 仍不能授权教学。长句原速连续三次、快速上传连续三次均得到完整相同转写；这不是对任意网络条件的可靠性保证。

### 2. 已录完的音频不再重复按原长上传

原来每 100 ms 发送 100 ms 音频，录完后在转写、教学各等一遍，还含 1.2 秒尾部静音。最终仍按 3200 字节分帧、逐帧让出事件循环以响应取消，但默认不再人为等待 100 ms。

依据：[官方 Java SDK 的 appendAudio 说明](https://www.alibabacloud.com/help/en/model-studio/omni-realtime-java-sdk)：关闭 turn_detection 后可手动提交音频缓冲；本实现保持现有短帧和输入大小上限，没有采用巨大单包。真实快速上传曾因旧时序失败，修正时序后才接入默认路径，失败日志保留。

同一句约 4.9 秒长口述，修复时序后的原速探针为 7.70 / 6.86 / 7.08 秒，快速上传探针为 1.73 / 0.78 / 0.68 秒。分别三次、小样本，含连接波动；不是生产 P95，也不是孩子说话开始到回复的总时长。

### 3. 教学握手失败恢复一次，已发送音频不重放

仅在握手/会话配置阶段、尚未发送任何音频时，对连接关闭/连接失败/超时重连一次。第一帧发送后即禁止此重试，即使尚未收到 commit 回执。用户取消、配置错误不重试。测试覆盖首次连接失败、持续失败、append 后失败、commit 后失败、取消五种边界。

### 4. 教学自然度：有改动，但不宣称已解决

明确不要将已知关系换成“对吗”重复确认；有结果时优先询问理由/检验。宿主探针最后一句仍偏确认；最终真机甚至问“你算出0.3米是7角2分，那2.4元买1米怎么来的呢？”，错误追问题干给定条件。**教学质量没有修好，不能把提示词断言或 UI 通过当作教学通过。**

另外尝试了缩短普通教学提示，真实探针却回复“你先把一米分成十份，每份多少钱？”，退回孩子已说过的步骤。该实验未进入交付代码，已恢复真机测试使用的提示版本；保留 `ai-dtl-compact-real-loop.log`。下一步需要调整教学动作选择及当前证据的组织方式，而不是继续追加同义提示。成功的接续收尾提示未改。

测试输入为既有合成语音和合成题图/画线，真实 Fastify WebSocket、真实 WorkspaceStore、真实千问。工具：`tools/probe-natural-loop.mjs`，会话完全隔离，未访问家庭记录。
