# AI-DTL：接手 Agent 的开发、模拟测试与真机验收手册

适用项目：**AI 学科心智学习系统（AI-DTL）**。本文写给只拿到仓库、没有参与前期讨论的实现 Agent。

这不是一份“代码怎么编译”的说明。工作单位是一个孩子能连续使用的学习过程：拍题、确认、表达、讨论、修改、检验、暂停与恢复。写代码只是其中一步。

> 核心要求：可以模拟孩子的输入，不能伪造老师的输出；可以自动操作设备，不能把模拟过程说成真人体验；完成要有证据，不是“应该可以”。

## 1. 先理解要交付什么

我们的目标不是让孩子听完答案，而是：**孩子先独立思考与表达，AI按证据给一小步帮助，最终交还控制权。**

- 五年级上、人教版是当前教学边界。以12.5÷0.5为例，主线是两个数同时乘10，转成整数除法；不擅自改成除0.5乘2的技巧课。
- “不会”要得到可尝试的小动作，不是换句话继续问为什么。
- 孩子换成钱、长度、画图、列表等思路，要先接住，不强迫回到某个预设图式。
- 孩子纠正老师，要核对、承认并修正；不能只说“你很棒”。
- 新的明确口述修正不能被旧照片错答覆盖。过去老师说过的话也不是数学真理。
- 算对、复述老师、模型JSON合法、`handoff=true`，都不能单独证明理解或掌握。
- 题干、课程、教学决策、语音、画布、学习记录各司其职，不为修一个问题引入新的Agent平台。

“任务完成”至少要回答：改了什么，原来怎么失败，现在在哪条真实路径上观察到不同，没覆盖什么。

## 3. 每轮先写一张小任务卡

不用为小修复写几十页设计，但开始前要固定以下内容：

```text
目标：同一道题暂停再继续，不把原照片40当作孩子最新答案。
原始失败：作品/目标回合/图片哈希/孩子最新原话/老师实际回复。
改动范围：只改来源与时序处理，保留语音和存储合同。
验收：保留原照；恢复后承接最新24；不重复已解释问题；同作品继续新增回合。
预算：本轮最多30分钟、12次真实API请求；错误/改写/复核也计入。
数据边界：新隔离目录、新测试作品，不写家庭档案。
停止条件：达到预算；或同方法连续失败，转为定位并交付证据。
证据：单测日志、真实回放、xcresult、两端记录对照、未覆盖项。
```

数字只是任务卡示例，不是每个任务固定配额。按风险与用户约定设上限，实验前固定，不能看到失败后悄悄加次数。

用户授权范围内自主继续：生成夹具、运行相关检查、定位失败、修复、复测、归档。不因为单测绿了就停，也不把“继续”理解成可以无限调用或扩大工程。

## 4. 复现时先保留失败现场

每个问题至少保存：

1. 确认后的题干、课程、题意revision。
2. `sessionId`、`turnId`、`responseId`以及当时的提交、反馈。
3. 原照片、当前画布预览、孩子原话；注明来源、时间与是否模拟。
4. 实际老师回复、决策字段、校验拒绝原因。
5. 当前源码哈希、模型ID、推理档位、主机/设备、启动参数与时间。

不要只截“老师说错了”这一句话，也不要立即清空草稿重测。先区分：识题错、转写错、上下文错、教学决策错、权限误拦、播报不一致、播放失败、UI/测试驱动失败。

固定目标回合回放时，必须截断未来历史：只给目标之前的老师反馈、当时已有提交及本轮孩子表达。不能把后面孩子报出的24、正确答案或目标老师原回复偷偷放回输入。历史老师错话可以作为待核对材料，不作为正确性证据。

## 5. 用分层验证提高速度，但每层结论必须清楚

| 层次 | 做什么 | 不能因此宣称什么 |
| --- | --- | --- |
| 单元/合同 | 状态转换、权限、证据编号、幂等、提示构建、校验 | 真人对话顺畅 |
| 本机集成 | 真实路由/存储、断线恢复、音频格式与回合 | iPad安装与设备播放通过 |
| 真实API定点回放 | 用存档证据观察真实模型输出 | 完整应用流程通过 |
| 实体iPad自动化 | 真实界面、通信、保存、暂停、退出重开 | 光学拍照、真人麦克风、实体Pencil手感通过 |
| 真人体验 | 相机、儿童原话、Pencil、扬声器、等待与打断 | 长期教学有效性已证明 |

针对新逻辑先写能暴露缺陷的测试，观察失败，再实现通过。不要为了流程删掉正确实现，不削弱有效测试。类型错误若是既有问题，记录其位置与影响，继续不受阻的部分；不能改口说全量通过。

## 6. 不靠用户点：怎样模拟完整的学习过程

### 6.1 先隔离，再启动

使用新测试目录、新作品ID、新缓存ID。宿主复用真实的`buildLearningTutor`与`WorkspaceStore`，显式传独立store，监听隔离端口；不要默认落到家庭正式库。

`apps/agent-host/scripts/probe-division-dialogue.ts`可作为现有同源隔离宿主/协议探针参考。它需要绝对路径的`AI_DTL_PROBE_DIRECTORY`；非serve模式还依赖指定照片、PCM夹具。不要把一个空目录传进去就以为已经准备好验收。

检查环境时只确认配置存在、结构有效，不读取/回显密钥。API密钥由用户在目标环境配置，运行进程加载；源码、截图、文档与日志都不保存密钥或请求头。

### 6.2 模拟照片：注入相机输出，不注入识别答案

现有`FiveTopicPhotoLearningUITests.swift`使用UIKit生成带题目、可选错答的照片，经DEBUG隔离入口进入真实识图，再实际操作候选选择与题意确认。

必须检查：

- 识别有可见进度/失败/重试，不是拍完没有任何变化。
- 多题先选题，再确认；不能悄悄替孩子选。
- “请重新拍照”等状态说明不能进入题干，手写错答不能并入印刷题目。
- 确认前不进入讲解；确认后原照片仍保留。

这是相机输出层模拟，不证明实体相机对焦、曝光、裁切和真实手写OCR已通过。

### 6.3 模拟孩子语音：给真实链路输入真实音频

此前使用macOS Tingting合成孩子文字，再转换成输入协议要求的16kHz、单声道、16位小端原始PCM。老师回复仍来自真实模型。

```sh
say -v Tingting -r 180 -o "$DTL_EVIDENCE/child-01.aiff" '我还是不会，给我一个具体小动作。'
ffmpeg -v error -n -i "$DTL_EVIDENCE/child-01.aiff" -ar 16000 -ac 1 -f s16le "$DTL_EVIDENCE/child-01.pcm"
```

`DTL_EVIDENCE`必须先设为本轮新建的绝对私有目录；确认声音与转换工具可用。PCM不是带头的WAV，不要把文件改扩展名冒充转换。现有老师输出协议是24kHz，不能把16kHz孩子输入直接按24kHz播放。

链路应经过真实的音频提交、转写、权限、决策、播报与客户端完成事件。不能直接把预想转写塞到最终反馈里，然后声称语音识别测试通过。仅测试决策时可直接输入文字，但明确不覆盖语音链路。

### 6.4 两类测试都要有，目的不同

**固定脚本回归**：预先写好孩子的话，稳定复现同一个问题；适合合同、边界和版本对比。若老师走向已经不同，固定脚本不再合理，要记录不匹配，不能冒充自然对话。

**自适应模拟**：每轮等真实老师回应完成后，读取回复、焦点与有效记录，决定孩子下一句。不会就继续求助，答错就坚持或改正，老师忽略新思路就追问，老师说错就质疑；不要无论老师说什么都接固定正确答案。

伪代码仅说明控制顺序，不是可直接运行的完整驱动：

```text
创建隔离作品，真实识图并确认
等待老师本轮 responseDone / 播报结束
读取实际回复、作品ID、反馈数、记录版本
决定一个与刚才回复相符的孩子反应
生成该反应的PCM
确认作品ID及老师回合数仍与刚才读取一致
提交一段孩子音频，等下一轮完成并保存实际结果
到了检查点，由UI执行真实暂停/重开
达到轮数、时间、请求预算即停止并归档
```

控制器不能排队向旧状态发音频，也不能悄悄替App重连来掩盖暂停恢复失败。

### 6.5 现有自适应harness的约定

五题验收归档中的`server.ts`与`input.mjs`保留了先前实现，主要契约为：

| 入口 | 用途与门禁 |
| --- | --- |
| `GET /harness/status/:case` | 读取实际作品、版本、孩子/老师回合 |
| `POST /harness/input/:case/:index` | 提交`sessionId/text/pcm/teacherCount`，作品或老师回合变化则拒绝 |
| `GET /harness/audio/:case/:index?sessionId=...` | iPad拉取下一段；404等待、200输入、204结束 |
| `POST /harness/finish/:case` | 指定本隔离作品的结束位置，不等于孩子掌握 |

这些是**测试适配器**，不是正式应用API。归档脚本包含旧临时路径、旧截止时间和设备标识，不能原样启动；先读脚本、迁移到本轮新目录、设新预算、匹配UI入口。没有现成适配器就补一个最小隔离驱动，不把缺控制器造成的等待误判成教学失败。

## 8. 至少测一条完整路径，再扩题型

最小闭环检查单：

- [ ] 拍题/选择照片后有反馈，候选与确认可见。
- [ ] 题干与原照保留，确认后才进入讨论。
- [ ] 孩子表达被正确关联到当前题目与回合。
- [ ] 老师先回应当下问题，不抢答案、不机械重复，不伪造画布内容。
- [ ] 孩子说不会、答错、换思路、质疑老师时都能继续。
- [ ] 老师确实生成音频，客户端收到并完成播放；若未实际听验，明确扬声器/听感未覆盖。
- [ ] 同题连续多轮；点击暂停后继续；未先暂停直接退出重开，再继续同题。
- [ ] 重开不自动开麦，作品ID/题意稳定，最新纠正不被旧图覆盖。
- [ ] 完成后交还独立尝试，保存并重开可见；不宣称已掌握。
- [ ] 失败/取消后按钮可用、原稿仍在，不陷入“本轮未完成”且无法继续。

布局/画布改动还要检查横竖屏、长聊天不推动按钮、工具可达、上下边缘书写、撤销/擦除/清除及照片/题意修改/冲突。XCUI在PencilKit画布拖画证明触摸路径可用，不能冒充Apple Pencil二代的压感、掌托和真实书写手感。

不能只测老师接一句话。也不要一开始五题全并发，把设备/宿主竞争和教学失败混在一起：先一题跑通连续过程，再分题扩展。

## 9. 数据审计：不能只说“界面显示已保存”

比较主机记录与iPad导出的同一隔离作品，至少核对：

- `sessionId`与`revision`；题意及题意revision。
- 提交与反馈数量、唯一ID，老师决策与反馈按`turnId/responseId`对应。
- 本轮非空孩子表达引用当前回合证据，不只引用旧图片。
- 未解决问题、笔迹数据、`boardRevision`、原照片SHA-256。
- 预览媒体存在且哈希相符；保存完成后没有悬挂的`pendingSave`。
- 争议/撤销/冲突按预期保留，不被重放错误恢复。

过去五题验收中每题“老师数=孩子数+3”，是因为有首次开场、暂停续聊、重开续聊三次额外回应；这是那套测试的具体结构，不能当所有学习会话的通用公式。

修改涉及家庭正式作品时，先保留必要私有备份，验收前后比较未触及草稿哈希。完成隔离验收不等于已经在家庭正式数据上重跑；健康接口成功只证明宿主可应答，不证明新代码已加载或孩子能完成学习。

## 10. 教学质量、延迟、费用要一起测

看真实老师回复，而不是只断言JSON能parse：

| 检查项 | 典型失败 |
| --- | --- |
| 数学与证据 | 5到10米说成两段；把只画两棵说成三棵 |
| 当前困难 | 问为什么却只报口诀；再求助却重问同一句 |
| 独立性 | 孩子没算出1.44，老师先替他算出 |
| 纠正与恢复 | 不承认自己说错；旧照片40覆盖最新24 |
| 动作与语言一致 | 嘴上交还，`focus/handoff`却继续追问 |
| 自然连续性 | 换了思路还走原流程；恢复后逐字重播表扬 |

做模型/提示对比时：先固定样本、评分、上限；保留相同事实与图片；记录模型ID、档位、完整输出、提示/图片哈希；错误和超时同样保留。思考Token只存计数，不保存思维链。

延迟至少区分完整决策、首音频、端到端；只测到一种就写一种。按用途统计识题/转写/决策/复核/播报，所有子调用都计入总调用预算。未知usage或价格记`null`，思考若已计入输出，不再加一次。实际账单、公开标价估算、含缓存折扣与不含语音费用必须分清。

10月11日对照的教训：非实时思考首轮更好但约9秒，续聊仍抢答；精简提示更省但没更会教；轻量校验全通过也可能教学失败。完整模型链路还含复核/改写，不能把首稿探针的成本/延迟称为正式链路成本/延迟。

已有`probe-teaching-ablation.ts`、`teaching-ablation-core.ts`、`report-teaching-ablation.ts`可参考。但探针已被后续Agent扩展，且仍有旧绝对截止时间；**不要复制10月11日命令就开始收费调用**。先重新审阅场景、回合来源、预算计数与实际模型调用数；旧结果只能用于离线复核。

## 11. 失败后怎么推进，而不是反复说“卡住了”

1. 先读日志、当前元素树、回合与源码哈希，确认真正失败层；不立即改提示。
2. 设备锁屏/信任待确认：只问一次具体动作，其他本机/后端检查继续。
3. 没有网络：检查实际连接路径，区分设备调试与业务网络；不凭USB线推断业务可用。
4. 没有老师音频：依次检查决策被拒、播报校验、音频生成、收包、播放完成与音频路由。文件非空不等于孩子听见。
5. 测试驱动没及时喂下一段：记录控制器失败，不算产品失败/通过，更不能让驱动自动重连遮住产品问题。
6. 同一方法连续两次失败就换诊断路径；第三次不继续同样重试。达到预算停止外部调用，保留证据与最小下一步。
7. 门禁误拦：补正例与反例，修根因。不删除权限检查、不放宽有效测试、不靠无限模型改写。
8. 本轮仍有安全、已授权且有意义的下一步就继续；真正缺输入或权限时具体说明影响范围，不让整项工作无声停下。
