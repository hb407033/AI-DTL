# 设计稿评审：AI 学科心智学习系统

- 评审对象：`docs/superpowers/specs/2026-08-30-ai-scholar-learning-system-design.md`
- 档位：红线档（儿童隐私数据流向、权限边界、长期数据模型）
- 第一轮（对 v0.1）：4 项 P0、5 项 P1、2 项范围前置、3 项伦理 —— **全部已被 v0.2 采纳**，第 19 节的三条"调整后接受"理由均成立（尤其把总往返 700ms 拆成本地打断 200ms + 首段音频独立 P50/P95，比原意见更专业）。第一轮意见不再重复。
- **第二轮（对 v0.2）：以下全部是修订本身引入的新问题。** 其中 R0-1 会使 5.0 表中一整行永远不可达，R0-2/R0-3 会使已承诺的儿童控件在运行时被系统拒绝，R0-4 会污染成长账本。

## 一、P0 · 修订引入的硬矛盾

### R0-1　提示预算与 4 级演示互斥，`INTERVENING → RECONSTRUCT` 是死转换

5.4 写"单个挑战**默认最多两次升级**"。从 0 级起两次升级只能到 **2 级**。

但同节又写"需要进入 **3 级或 4 级**时，本轮不再计作独立成功"，5.0 表还有一行 `INTERVENING` +「已使用 4 级完整演示」→ `RECONSTRUCT`，5.4 另有"进入 4 级完整演示前必须至少有一次孩子侧实质性尝试"。

**在两次升级的预算下，3 级和 4 级永远到不了**，上述三处规则全部不可达；而 5.0 表里 `INTERVENING` +「提示预算耗尽」→ `SOFT_LANDING` 会先一步把路径截走。`RECONSTRUCT` 状态、4 级演示、"演示后必须重建"这一整条最重要的教学链路，在当前规则下**是死代码**。

必须二选一并同步改 5.0 表：
- (a) 预算改为"最多 4 次升级"，另设"到 2 级后需满足 X 条件才继续升"；或
- (b) 保留两次升级为**软预算**，明确写出解除条件、解除者（本地内核，非 Codex）和记账后果。

无论选哪个，5.0 表 `INTERVENING` 行必须补上"预算耗尽但满足升级条件"与"预算耗尽且不满足"两条互斥转换，否则实现者只能靠猜。

### R0-2　常驻控件与"未列出转换默认拒绝"正面冲突（休息）

5.2 和 8.1 都承诺"我想休息"是**常驻入口**。但 5.0 表中 `PAUSED_CHILD` 的入口**只有 `INDEPENDENT` 一行**。表末尾的三条"任意活动状态"通配只覆盖了转写不确定、技术中断、输出不合规。

而 5.0 明写"未列出的转换默认拒绝并记录策略错误"。

后果：孩子在 `EXPLAIN_BACK`、`TRANSFER`、`RECONSTRUCT`、`ASSESSING`、`SOFT_LANDING` 中按下常驻的"我想休息"，**系统会拒绝并记一条策略错误**。恰恰是讲回和迁移这两个最累的环节，孩子最需要退出。

修：把 `PAUSE_REQUEST` 提升为"任意活动状态 → `PAUSED_CHILD`"通配行。

### R0-3　同一冲突的第二处（异议）

8.1 承诺"你理解错了"常驻，8.5 规定触发后"**立即**停止当前诊断性追问"，10.2 有 `CONTEST` 事件类型。

但 5.0 表中 `CONTESTED` **只有出口没有入口**——唯一入口是 `MEMORY_PENDING` +「孩子选择"不是这样"」。孩子在 `INTERVENING`（AI 刚说错他的想法）或 `ASSESSING` 时触发异议，表里无转换 → 默认拒绝。

**而"AI 说错了"最常发生的时刻恰恰就是 INTERVENING**，这是异议权最需要生效的地方，也正是当前表拒绝它的地方。

修：补"任意活动状态 + `CONTEST` → 保持当前状态，冻结相关假设、停止诊断性追问"。8.5 的动作不一定需要换状态，但**必须有显式表项**，否则"默认拒绝"会吃掉它。

### R0-4　软着陆后的"辅助轮"标记没进状态机，会污染成长账本

5.6 要求"任何后续辅助都明确标记为'不计入本次迁移验证'"，5.0 表 `SOFT_LANDING` 两行的动作列也写了"标记为辅助轮"。

但**这个标记是会话级的，而状态机不携带它**：`SOFT_LANDING` → `INTERVENING`（看提示）之后，孩子若产生新尝试，按表走 `INTERVENING → INDEPENDENT`，此后一路 `EXPLAIN_BACK → TRANSFER → MEMORY_PENDING` 的每一个状态，都与正常路径**完全同名同参**。辅助标记在哪一步被读取、由谁保证不丢，全文没有规定。

后果：**一次辅助轮的迁移成功，会被 `GrowthLedgerService` 当作无提示迁移成功写入长期记录**——这正好击穿 9.3"做对原题不算毕业"和 5.6"迁移失败不宣布掌握"这两条核心承诺，而且是静默发生的。

修：把 `assisted_round`（或 `verification_void`）设为**会话上下文的一等字段**，写进 5.0 表的动作列（`SOFT_LANDING` 出口置位、新挑战 `PREPARING` 时清零），并在 10.7 `MemoryCommitDecision` 增加一条门禁：本轮 `assisted_round` 为真时拒绝提交档位 2/3。15.1 增加对应用例。

### R0-5　主路径的 happy path 在转换表里不存在

`INDEPENDENT` 的三个出口是：仍有新产出（自环）、求助/卡住/**无新策略达到窗口下限**（→`ASSESSING`）、暂停（→`PAUSED_CHILD`）。

**孩子独立、顺利地做完了，走哪条？** 只能挤进"无新策略达到窗口下限"——但他不是没策略，他是做完了。于是最理想的学习路径必须伪装成一个"疑似卡住"事件，经过一个名为"评估是否需要介入"的状态才能到 `EXPLAIN_BACK`。

这不只是命名别扭：`ASSESSING` 的动作列写着"汇总本轮证据"，成功路径会因此产生一份本不该有的"介入评估"记录，并可能进入根因候选。

修：补一行 `INDEPENDENT` +「孩子表示完成，或产出满足 `expected_evidence`」→ `EXPLAIN_BACK`，动作为"不生成介入评估证据"。

## 二、P1 · 需要在编码前定清楚

### R1-1　两个状态是单出口死角

- `PAUSED_TECH` 唯一出口是「连接恢复**且检查点一致**」。**检查点不一致时无路可走** —— 而这恰恰是最需要设计的分支（部分写入、版本漂移、客户端重装）。至少要有 → `PREPARING`（丢弃未确认增量、从最后完好快照重开）并告知孩子。
- `WAITING_CONFIRMATION` 唯一出口是「孩子确认或修正」。孩子不回应、走开、或反复确认失败时无出口。需要超时 → 原状态并将该转写永久置为 `unconfirmed`。
- 另：`COMPLETED` → `PREPARING`（同一会话里做下一个挑战）在表中缺失。一次学习会话显然不止一个挑战。

### R1-2　"不推断情绪"需要一个补偿闸：探索窗口的硬上限

5.2 的延长规则是"只要孩子持续产生新笔迹或新策略就自动延长"。但 8.4 明确把"**是否擦除、反复修改**"列为证据类型——**一个焦虑的孩子会不停地画了又擦**，这在 5.2 的判据下会被读成"持续产生新笔迹 → 仍在生产性探索 → 继续等待"，从而无限延长。

第一版正确地放弃了情绪识别（我认同这个选择），但**放弃情绪识别之后，"反复擦改"就是系统唯一能看到的挫败信号，而当前规则把它读成了正面信号**——方向正好反了。

修：(a) 单次独立探索窗口设硬上限（建议 3–5 分钟），到时**强制进入 `ASSESSING`**（是评估，不是提示）；(b) 5.2 的"新笔迹即延长"排除"擦除后重画到相同内容"这类无进展循环，或至少不把它计为新策略。

### R1-3　200ms 打断隐含平板本地 VAD，但设备验证没点明

11.3.1 那条"打断必须在平板本地完成，不能等待 Codex 往返"是全文最专业的一条工程判断。但它隐含要求平板本地跑 **VAD（语音活动检测）** —— 而 15.4 的设备验证页只写了"录音、播放、**打断**、画一条线、局域网 HTTPS 和断线重连"。

"打断"若被实现成一个按钮，会测出 20ms 然后通过门禁，真实场景再失败。iOS Safari / standalone PWA 下 AudioWorklet 跑 VAD 的可行性正是这里的真实风险点。

修：15.4 明确写成"**由本地 VAD 检测到孩子开口而触发**的播放停止"，并把 AudioWorklet 可用性列为该验证页的显式检查项。

### R1-4　`intervention_budget` 的强制方未定，且不在校验清单里

10.1 新增了 `intervention_budget` 字段，但没说默认值由谁给：内核常量、插件清单、还是挑战生成器（即 Codex）？

若 Codex 能在提案里影响预算，它就能给自己开额度——**这会绕过 5.4 的全部约束**。

而 10.3 的本地校验清单是"提示级别、文本长度、学科合法性和画布动作"，**不含预算校验**。

修：明确 `intervention_budget` 上限由本地内核强制，插件与 Codex 的提议只能更严不能更松；10.3 校验清单加入"预算与升级门禁"一项；15.1 加一条"Codex 提议超预算被拒"的确定性用例。

### R1-5　4 级演示之后迁移成功，到底能不能写入长期记录？

5.4 说"需要进入 3 级或 4 级时，**本轮不再计作独立成功**"。
5.6 说"**只有迁移成功**，临时假设才有资格成为长期成长记录"，而 `TRANSFER` 阶段提示级别归零。

于是"4 级演示 → 重建 → 讲回 → 0 级迁移成功"这条路径，两条规则给出相反指示，文档没有裁决。实现者会随手选一个，且两种选法都能自圆其说。

我的建议（供拍板）：**应当允许写入**——这正是学习发生的样子，禁止它等于惩罚需要帮助的孩子。但写入的记录必须携带"本次达成用过 4 级提示"，且该轮的 `ScaffoldDependencyPoint.max_hint_level_used = 4` 照常计入退出趋势。请在 5.6 明确一句。

### R1-6　`ScaffoldDependencyPoint` 与孩子知情框架的灰区

9.5 承诺"孩子随时可以查看**系统目前怎么理解我**"，且长期记录须经孩子同意。5.7 则说退出趋势"是系统质量指标，**不作为孩子可见的分数或排名**"。

问题：SDP 数据来自所有会话，还是只来自孩子同意写入的记录？
- 若来自所有会话 → 系统保留了孩子未同意的、关于他的判断数据，只是换了个名字叫"质量指标"；
- 若只来自同意的记录 → 孩子的同意行为会污染教学质量指标，趋势失真。

技术上我认为应选前者（SDP 不含能力结论，只有提示级别与时间，属系统自评）。但**"不作为孩子可见的分数"不应被实现成"对孩子隐藏"**——那与 9.5 的承诺相抵。

修：明确 SDP 属系统自评而非儿童评价，并在孩子的"系统怎么理解我"视图中以中性、非排名的方式**可见**（例如"最近这些题，你自己做出来了几次"）。这既守住 9.5，又恰好是最好的元认知材料。

## 四、判断

v0.2 是一次高质量修订：转换表、提示预算、写入权限、离散证据、区分性探针、幂等、实时预算、前置验证、儿童权利——每一项都不是敷衍地加一句话，而是补到了可实现的粒度。6.2 那三个区分性探针（先问大小 / 让其自查 / 换无小数点的同构表示）写得尤其好，是全文最能直接落地的一段。14.6 的四阶段划分比我原来的"砍到单挑战"更妥当。

但**新增的严格规则之间还没有互相对表**：R0-1（预算 vs 4 级）、R0-2/R0-3（默认拒绝 vs 常驻控件）、R0-4（软着陆标记 vs 账本门禁）都是"两条各自正确的新规则叠在一起产生了错误行为"。这是引入形式化规则后的典型第二轮问题，不是设计倒退。

**建议：R0-1 ~ R0-5 修订后即可终审通过。** 这五条都只需改 5.0 表和 5.4/5.6 的措辞，不触动架构。R1 六条建议同批处理，因为它们都会影响第 3 阶段之前的实现选择。R2-6 那条元规则建议优先加，它能一次性防住 R0-2/R0-3 这一类漏洞的复发。
