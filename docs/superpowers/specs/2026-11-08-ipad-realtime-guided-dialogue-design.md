# iPad 端实时引导对话：设计

日期：2026-11-08。状态：设计已与用户逐段确认，待写实施计划。

## 背景与目标

现状（mini 宿主 v16）：孩子说完一句，经 iPad→mini→云端 转写 → 文字模型决策（深度思考）→ 规则门禁（不过则重写）→ 模型复核 → 语音合成 → 回传 iPad。顺利 6–8 秒，重写一次 10 秒以上。2026-11-08 真机使用反馈：等待过长、学习过程割裂。

目标：

- 孩子说完到听见老师，常态 2–4 秒；全程有"被听见"的反馈，不再有沉默。
- 引导式教学不变：不抢答、不教口诀捷径、一次只推进一个问题、承接孩子刚说的话。
- 孩子听到之前仍有把关；语音与文字一致。
- 给自家孩子日常使用；数据最终落到 mini。

已确认的取舍（用户 2026-11-08）：

- 课堂节奏选 **混合型**：孩子求助/提问走快路径；孩子说想法、自言自语、写画时老师只应一声，不接话。
- **千问密钥放到 iPad**（钥匙串），iPad 直连云端；mini 退为数据后端。离家、mini 离线也能上课。
- 教学质量与速度冲突时，接受"大多数轮次快、少数被拦下的轮次慢"。

## 1. 整体结构

```
iPad（教学在这里跑）                         mini（只存数据）
┌──────────────────────────────┐           ┌──────────────────┐
│ 麦克风 / 画布                 │           │ 作品库 workspaces │
│   ↓                          │           │ 教学决策历史       │
│ 实时语音会话 ⇄ 千问云端        │  ──同步──▶│ 用量记录           │
│   ↓ 声音 + 文字               │           │ 家长查看           │
│ 本地把关（JS 规则，毫秒级）     │           └──────────────────┘
│   ↓ 通过                      │
│ 扬声器                        │
└──────────────────────────────┘
```

- 教学决策、把关、播放都在 iPad 上闭环，没有中转。
- 规则门禁不重写成 Swift：现有 TS 门禁打包成 JS，iPad 用 JavaScriptCore 运行。mini 与 iPad 同一份规则源码、同一套测试。
- mini 接收 iPad 推送的作品、决策、用量；iPad 离线先存本机，联网后补推。mini 上现有教学路由（v16）保留，默认不用，作为对比实验与回退。

## 2. 一轮对话（混合节奏）

孩子说完一句（iPad 检测到约 1 秒安静）后：

```
孩子的录音 + 当前画布照片（只在有新笔迹时附）
        │
        ▼
实时模型一次调用，同时产出：
  ① 孩子说的文字（转写）
  ② 这句话的类型：求助 / 提问 / 说想法 / 自言自语 / 结束
  ③ 老师的回答：声音 + 对应文字（只在 ①② 判断该回答时才生成）
        │
        ├── 自言自语 / 说想法 → 取消 ③；iPad 放预录的"嗯"。记下文字供下一轮上下文
        │
        └── 求助 / 提问 → ③ 的声音先缓冲在 iPad，不放
                   │
                   ▼
            本地把关（JS 规则，毫秒级）
                   │
                   ├── 通过 → 立刻播放（预计 2–4 秒）
                   │
                   └── 不通过 → 丢弃声音，走慢路径：
                         文字模型按拒绝原因重写一次 → 规则再查 → 模型复核 → 合成 → 播放
                         （即现有流程；iPad 先放预录的"嗯，让我想一下"）
```

关键决定：

1. 同一条连接、同一段录音，拿三样东西：先要一次**只有文字**的响应（一行 JSON：类型 + 转写，几百毫秒内到达），再按类型决定要不要第二次**文字+音频**的响应。分两次是因为音频模式下模型会把文字念出来，JSON 不能和老师的话在同一个响应里；"自言自语"根本不发第二次响应，没有音频成本。
2. 老师主动开口的两个时机（陪伴部分）：孩子停下超过约 40 秒且画布有新笔迹，附照片问一次；孩子写出一步关键内容（本机 OCR 看到等号右边出现新数）可以问一次。都走同一条快路径和把关。秒数先定初值，使用后调整。
3. 把关失败走慢路径而非放弃："快"是常态，"慢"只在模型没守规矩时出现；孩子永远听不到被拦下的那句。
4. 深度思考与模型复核只在慢路径用。快路径质量靠：给实时模型的提示词（现有教学提示词的语音精简版）+ 本地规则。

## 3. 把关规则在 iPad 上运行

打包：

- 用现有 esbuild 打包工具，把 `workspace-teaching-decision.ts` 中的纯规则部分（`validateTeachingDecision`、`keepOneQuestion`、`plainRepair`、题目解析与求解器、`matchesTeachingQuestion` 等）打成独立的 `teaching-gates.js`：无网络、无文件操作、无密钥。
- iPad 用 JavaScriptCore 加载。Swift 入口只有一个：

```
TeachingGates.check(draft: 老师这句话的文字, context: JSON) -> 通过 | 拒绝(原因, 可自动改写后的文字?)
```

- `context` 为现有门禁输入的 JSON：题目文字、孩子最近几句、历史决策、是否附了照片、本机 OCR 看到的数。门禁不看图片，不向 JS 传照片。
- 规则返回改写文字时，原声音与文字已不一致，**改写即走慢路径**，用改写后的文字合成。

慢路径也在 iPad 上跑：

- `QwenTeachingDecisionProvider.decide`（重写 + 模型复核）和 `speakDecision`（合成并核对）一并打进同一个 JS 包。它们的网络调用已经是可注入的（构造时传入 `requestText`），由 Swift 提供实现：文字模型走 HTTPS，合成走 iPad 自己的实时连接。JS 包本身仍不含网络代码和密钥。
- 这样快路径、把关、慢路径三者都在 iPad 上，mini 离线时三者都可用。

两端一致：

- 规则源码只有一份；mini 与 iPad 各自打包，清单记录源文件哈希。
- 现有 561 项主机测试继续覆盖规则；新增 iPad 对照测试，用 JavaScriptCore 跑约 30 个"应拦/不应拦"样例，两端结果必须相同。

实时会话内容：

- 进入一道题时建立长会话：题目文字、课程边界、语音版教学提示词、前几轮要点一次性放入会话指令；之后每轮只发录音，有新笔迹才附照片。
- 会话断了用本机保存的要点重建。
- 每轮两次响应：头部响应只有文字 `{"transcript":…, "kind":…}`；回答响应是老师的话（文字 + 语音）。iPad 对回答做一次数字一致性轻量核对（同 `matchesTeachingQuestion`，在 JS 包内）。快路径只有老师的一句话，决策骨架（焦点、证据引用等默认值）由 JS 包补齐后再过门禁。

密钥：

- 千问密钥存 iPad 钥匙串。首次配置由家长在"家长设置"里从 mini 拉取一次（局域网，mini 端确认），之后不再传输。日志与同步数据中永不出现密钥。

## 4. 连接、语音输入时序、成本

### 4.1 边说边传，不是说完再传

```
孩子开口 ──────────── 孩子说完 ──── 1 秒安静 ──── 模型回答
   │                      │              │
   ▼                      ▼              ▼
检测到开口              最后一帧传完     发"说完了"
开始逐帧上传录音        （与说话同步）    模型已听完，立即出结果
```

- iPad 已有"检测到开口"事件（现用于打断）。开口即逐帧上传，省掉整段上传时间，模型同步处理。
- 连接建立安排在这个窗口：孩子一开口就确保连接在。一句话至少 2–3 秒，握手 0.4–0.6 秒，来得及；握手期间录音本地缓冲，连上后按序补发。不需要常开热备。
- 录音帧按序编号；"说完"信号一定在最后一帧之后。

### 4.2 连接生命周期跟着活动走

| 时刻 | 动作 |
|---|---|
| 点"一起聊聊" / 确认题目 | 建一条连接（预热） |
| 对话进行中 | 复用，不重建 |
| 空闲超过约 90 秒（无说话、无新笔迹） | 主动关闭 |
| 之后孩子再开口 | 开口瞬间重建，录音本地缓冲，连上后补发 |
| 连接意外断开 | 对话中立即重建；本就空闲则不重建，等下次开口 |

### 4.3 成本

现状每轮：转写 1 次 + 文字决策 1–4 次（每次 2,600–6,200 token，均带照片）+ 模型复核 1 次（带照片）+ 合成 1 次 ≈ 8,000–20,000 token、照片 2–5 张；被拦下重写的轮次最贵。

新设计每轮：

- 快路径：实时模型 1 次，照片只在有新笔迹时附 1 张；
- 自言自语：只有音频输入，判定后立即取消生成，无输出成本；
- 慢路径才回到现状那套。

三个成本控制点：

1. 会话上下文累积：每 8–10 轮或上下文超限时主动换新会话，只带要点摘要。与空闲重建共用机制。
2. 照片：只在有新笔迹且孩子求助/提问时附；本机 OCR 的数字以文字带上。
3. 老师主动开口限频：间隔 ≥ 2 分钟、画布必须有新内容、一道题最多 3 次。

预计每轮 token 为现状的 1/3–1/5。iPad 记录每轮 token 与耗时并同步到 mini 的 usage 记录，用真实数字对比。

## 5. 数据落到 mini

原则：iPad 上课期间是现场，mini 是档案。上课不等 mini，每轮结果都会到 mini。

同步内容（格式不变，家长查看与现有工具照用）：

1. 作品记录：题目、笔迹、提交的证据照片、老师反馈（含异议）
2. 教学决策历史：每轮老师的话、焦点、证据、快/慢路径、把关结果；被拦下未播放的话也记入，标"未播放"
3. 用量：每轮 token、照片张数、说完到出声耗时
4. 媒体：画布照片，按内容哈希去重

方式：

- iPad 本机先写；每轮结束后后台推一次给 mini，失败进持久化队列，按序补推。上课不等 mini 回应。
- mini 新增按会话接收"记录 + 决策 + 用量"批次的接口，带版本号，重复批次只记一次。
- 现有"保存到学习主机"与版本冲突检测保留。一道题同一时间只在一台 iPad 上做，iPad 版本为准；mini 只在版本号倒退时拒绝并报告，不自动合并。
- mini 现有教学路由（v16）保留，不再被 iPad 调用。

离线：mini 关机或孩子在外面照常上课，数据排队；回家补推。队列持久化，App 被杀不丢。

边界：密钥、原始录音永不同步，录音用完即丢。

## 6. 打断、失败处理、测试与对比实验

### 打断

- iPad 检测到孩子开口即停止播放，并向实时会话发取消；取消与下一句录音走同一连接，不再等 mini 回执。
- 被打断的半句记为"被打断"，下一轮要点带上"上一句没说完"。
- 缓冲阶段孩子开口，直接作废这次生成。

### 失败处理（失败保留原稿，孩子永远有下一步）

| 情况 | 孩子听到/看到 |
|---|---|
| 连接建不起来、超时 | 预录"刚才没听清，你再说一遍好吗？"；状态条显示原因 |
| 模型输出格式不对（没有开头 JSON） | 当作"说想法"：只应一声，记下文字，不走慢路径 |
| 快路径被拦、慢路径也失败 | 预录"老师刚才没想好，你再说一遍好吗？" |
| 语音与文字数字不一致 | 丢弃声音，按文字走慢路径重新合成 |
| 同步 mini 失败 | 孩子无感；家长设置显示"待同步 N 条" |

所有失败记日志并同步到 mini（不含录音与密钥）。

### 测试

1. 规则层：561 项主机测试继续；JavaScriptCore 对照测试保证两端一致。
2. iPad 单元测试：实时会话状态机（预热、边说边传、补发、取消、重建、换会话）用假连接测；分帧顺序、离线队列、重复批次去重。
3. 真机回归：现有 5 类题脚本改为走新路径（孩子语音仍从 mini 取，但 iPad 直连云端）。每轮记录：说完到出声、快/慢路径、把关原因、token。

### 对比实验（切换前门槛）

同一批 5 类题、同一套孩子台词，v16 与新路径各跑一遍：

- 说完到出声中位数 ≤ 4 秒（现状 6–10 秒）
- 抢答、口诀不多于现状
- 慢路径占比 ≤ 30%
- 每轮 token ≤ 现状 1/2

四项达标才默认切换；切换做成开关，v16 随时可回。最后由家长真机开麦使用一遍，节奏认可才算完成。

### 实施顺序（写计划时细化）

1. 实测两个数：iPad 建连接耗时、云端会话空闲超时
2. 规则打包成 JS + JavaScriptCore 对照测试
3. iPad 实时会话客户端（预热、边说边传、取消、重建）
4. 快路径 + 把关 + 慢路径回退
5. mini 接收接口 + iPad 离线队列
6. 老师主动开口、会话换新、限频
7. 真机回归脚本改造 + 对比实验

## 不在本设计范围内

- 边合成边播放（放弃播前把关）：用户未选。
- 降低文字模型思考强度：仅影响慢路径，另行评估。
- 多台 iPad 同时做同一道题的合并。
- 长期能力档案的自动写入（沿用现有边界：会话工作记忆不自动进档案）。
