# AI 学科心智学习系统设计规范

- 版本：0.5（成长记忆层设计定稿引发的规范修订）
- 状态：已确认总体架构与原生 iPad 技术路线
- 日期：2026-08-30
- 首个使用者：小学五年级孩子
- 首个完整场景：人教版五年级上册数学“小数乘法”
- 首个通用性场景：一段文学细读
- 部署边界：家庭局域网，平板作为儿童端，Mac mini 作为 Agent 宿主
- 模型边界：Codex 实时能力作为第一版唯一主模型路径，不实现第三方回退

## 1. 产品定义

这不是一个“会讲题的聊天机器人”，而是一套帮助孩子形成学科心智的长期学习系统。

系统的成功标准不是孩子是否更快得到答案，而是当 AI 逐渐退出后，孩子能否独立完成以下过程：

1. 观察对象并提出问题；
2. 形成猜想或初步感受；
3. 自己建立表示、模型或解释；
4. 寻找策略与证据；
5. 检验、修正并讲清楚；
6. 将形成的方法迁移到新情境；
7. 产生可以回望、修改和积累的作品。

北极星原则：

> 孩子先独立建模，AI 根据证据逐级介入，并最终退出。我们培养的是数学家、文学家和其他领域的独立思考者，而不是只会做题的学生。

## 2. 目标与非目标

### 2.1 第一版目标

- 提供语音优先、画布优先的儿童专用界面。
- 支持孩子说、画、圈、拖、改、拍题和讲回。
- 在孩子独立探索后，根据行为证据判断是否需要帮助。
- 通过提示阶梯逐级介入，避免 AI 过早替孩子完成思考。
- 在可比挑战中持续降低孩子完成无提示迁移所需的最高提示级别，使“AI 最终退出”成为可检验目标。
- 将错题、作品、策略、讲回和迁移结果组织为可追溯的成长档案。
- 以通用学习内核承载可插拔学科心智插件。
- 完整跑通数学“小数乘法”纵向切片。
- 用一个最薄文学插件证明系统没有写死为数学辅导工具。

### 2.2 第一版非目标

- 不完整覆盖所有年级、学科和教材。
- 不实现第三方模型回退。
- 不开放校外远程访问。
- 不实现多孩子、学校班级和教师后台。
- 不以积分、排行榜和强刺激游戏化驱动学习。
- 不自动导入或分发整套未授权教材。
- 不把正确率、速度或题量当作学科心智成长的替代指标。
- 不把 Codex 的原始界面、长文本、工具调用或内部推理展示给孩子。

## 3. 专家议会与设计依据

系统不采用一个“万能名师人格”，而采用分工明确的专家议会。

### 3.1 通用学习机制

- **Seymour Papert：建构主义工作室。** 孩子通过制作可见、可讨论、可修改的作品建构知识。由此决定系统以画布和作品为中心，而不是以聊天记录为中心。
- **Manu Kapur：生产性失败。** 在直接教学之前，先让学习者生成方案、暴露结构并经历有价值的失败。由此决定 AI 先等待，只有失去生产性时才介入。
- **Kenneth Koedinger 等：认知模型与智能辅导。** 学习判断必须建立在细粒度过程证据上，帮助应发生在合适的问题情境中。由此决定证据解释、离散证据摘要和恰逢其时的提示机制。

### 3.2 学科心智

- **数学插件以陶哲轩的公开数学观为重要视角。** 核心是直觉与严谨互相校正，重视简化问题、特殊案例、反例、清晰论证、校验和迁移。这里是产品推演，不代表陶哲轩本人认可本系统。
- **文学插件以 Louise Rosenblatt 的读者—文本交易理论为重要视角。** 阅读意义由读者与文本的相遇形成；个人感受可以不同，但成熟解释必须回到具体语言和文本证据。

## 4. 总体架构

架构使用两个互补视图：三层功能架构说明职责边界，家庭部署架构说明组件运行在哪里。

### 4.1 三层功能架构

#### 教学智能层

负责课程目标、挑战生成、学科心智、题目或文本、解释、根因假设、提示策略和迁移任务。

它只产生教学建议，不直接控制儿童界面，也不能直接写入永久成长结论。

#### 互动呈现层

负责语音、语义画布、笔迹、圈选、拖动、批注、拍题、作品编辑和实时反馈。

它把所有交互转换为统一证据事件，并把通过本地校验的教学动作呈现给孩子。

#### 成长记忆层



负责原始事件、证据、临时假设、验证任务、作品版本、长期成长记录和复习节奏。

它不只是错题本。错题只是观察孩子学科心智的一类证据。

### 4.2 通用学习内核与学科插件

通用内核负责：

- 独立探索与提示阶梯；
- AI 介入和退出策略；
- 统一证据事件；
- 假设验证与长期记忆门槛；
- 画布同步、作品版本和会话恢复；
- `GrowthLedgerService` 的分级长期记忆门禁与离散证据摘要的计算（口径必须跨学科一致，且它是门禁输入，不能由插件决定）；
- `RealtimeBridge` 的生产、脚本回放和家长接管实现；
- 儿童控制权、隐私和本地策略校验。

学科插件负责：

- 本学科研究的核心对象；
- 学科特有的表示形式；
- 典型发问方式；
- 合法的探索和思维动作；
- 什么构成本学科的可靠证据；
- 作品与表达形态；
- 提示阶梯中的学科内容；
- 如何生成“表面不同、深层结构相同”的迁移任务。

每个插件必须回答七个问题：

`研究什么 → 怎样观察 → 怎样发问 → 怎样探索 → 什么算证据 → 怎样表达 → 怎样迁移`

### 4.3 架构铁律

- 通用内核不得定义某一学科的“好答案”。
- 学科插件不得绕过儿童控制权、证据要求、提示阶梯和 AI 退出规则。
- 课程版本和章节映射不得写进通用内核。
- Codex 协议字段不得泄漏到互动层、学科插件和成长记忆模型。
- 长期状态必须保存在 Mac mini 本地，而不是依赖模型上下文或聊天历史。
- 只有 `GrowthLedgerService` 能提交长期成长记录，且必须执行本地规则、儿童知情同意和必要的家长审阅。

## 5. 学习运行闭环

主路径为：

`准备挑战 → 独立探索 → 评估证据 → 必要时介入 → 孩子重建并讲回 → 无提示迁移 → 待确认记忆 → 完成`

失败、暂停和恢复是同一状态机中的显式分支，不能只写在异常处理章节。

| 当前状态 | 事件或条件 | 下一状态 | 必须发生的动作 |

| `PREPARING` | 挑战与课程依据校验通过 | `INDEPENDENT` | 创建会话检查点，提示级别归零 |
| `PREPARING` | 课程依据不足 | `WAITING_PARENT` | 冻结教学，等待家长确认材料 |
| `INDEPENDENT` | 孩子仍有新产出 | `INDEPENDENT` | 只显示非教学性在场信号，不提示 |

| `EXPLAIN_BACK` | 解释暴露新的断点 | `ASSESSING` | 更新临时假设，不提交掌握记录 |
| `TRANSFER` | 无提示迁移成功 | `MEMORY_PENDING` | 生成可读的成长记录预览与证据摘要 |

| `WAITING_CONFIRMATION` | 孩子确认或修正 | 原活动状态 | 写入确认事件并继续 |
| `WAITING_CONFIRMATION` | 超时无回应（默认 60 秒） | 原活动状态 | 该转写永久保持 `unconfirmed`，不作诊断 |

| `COMPLETED` | 开始下一挑战 | `PREPARING` | `assisted_round` 清零，提示级别归零 |
| 任意活动状态 | `PAUSE_REQUEST`（孩子或家长） | `PAUSED_CHILD` | 保存检查点，不形成负面判断 |
| 任意活动状态 | `HELP_REQUEST` | `ASSESSING` | 汇总本轮证据，不直接升级提示 |
| 任意活动状态 | `CONTEST` | 原活动状态 | 立即停止诊断性追问，被质疑的假设或教学动作转 `contested` 并冻结写入，问“哪里和你的想法不一样？”，允许跳过 |

### 5.1 生成挑战

输入包括课程目标、成长档案、到期复习项和学科插件。输出是一项完整挑战，而不是一串碎片化问答。

挑战必须同时包含：

- 学科目标；
- 儿童可见任务；
- 允许使用的表示和工具；
- 独立探索窗口；
- 预期观察证据；
- 提示阶梯；
- 讲回要求；
- 无提示迁移任务规格。

### 5.2 独立探索

- 默认呈现空白或最低限度的画布，而不是完整示范图。
- 孩子先说、画、举例、圈选、修改或尝试。
- 第一版不推断孩子的情绪，也不分析摄像头画面或声纹情绪。可用介入信号仅限明确的自我报告、主动求助、画布行为和任务进展。
- 初始无提示窗口以 30 秒为基线；只要孩子持续产生新笔迹或新策略就自动延长，不以沉默机械升级提示。擦除后重画出相同内容不计为新策略。单次独立探索有硬上限（默认 240 秒），到时进入 `ASSESSING` 做评估，而不是直接提示。
- 画布持续显示轻微的“我在这里”呼吸指示灯。它不包含学科信息、不计入提示级别，避免孩子把安静误解为系统故障。
- 常驻提供“我卡住了”“我想休息”两个入口，孩子可以主动结束等待。
- 只要出现新笔迹、新策略、自我修正或有效提问，就视为仍在生产性探索。

### 5.3 解释证据

系统先记录“发生了什么”，再形成“可能意味着什么”的临时假设。

错误本身不触发帮助。只有出现以下证据时，编排器才考虑介入：

- 重复同一无效路径且没有新变化；
- 长时间没有产生新策略；
- 孩子主动求助；
- 孩子明确说“我卡住了”“我不想继续”或使用对应控件；
- 当前路径会强化明显错误概念，继续探索不再有价值。

早期家庭试用要求家长在附近可被孩子主动呼叫，但家长不实时替系统推断情绪。若孩子出现明显不适，家长或孩子都可以立即暂停；暂停本身不得形成能力证据。

### 5.4 提示阶梯

提示内容分为以下级别：

0. 安静观察；
1. 元认知问句，例如“你现在确定了什么？”；
2. 方向暗示，例如建议尝试更简单案例；
3. 半成品表示，例如给出未完成的数轴或文本线索；
4. 完整演示，并明确标记为示范；
5. 回到孩子，由孩子重建、解释和迁移。

“每次最多升一级”还不够，编排器必须同时执行以下预算和降级规则：

- 每个新挑战都从 0 级开始；历史最高提示级别只用于选择挑战难度和观察退出趋势，不能直接成为新挑战的起始提示。
- 每次提示后必须先出现孩子侧的新产出，才允许再次评估是否升级；禁止连续自动播放多个提示。
- 单个挑战的软预算是两次升级。超过软预算继续升级，只能由本地内核在“孩子在上次提示后有实质性尝试，且再次明确求助”时解除，本轮 `independent_success` 置为 false 并记录最高提示级别；硬预算是最高 4 级、最多 4 次升级，耗尽即进入 `SOFT_LANDING`。
- `intervention_budget` 的上限由本地内核强制，学科插件和 Codex 的提议只能更严，不能更松；超预算的 `TeachingProposal` 一律拒绝。
- 进入 4 级完整演示前，必须至少有一次孩子侧实质性尝试；完整演示之后进入“孩子重建”，不得直接进入迁移或掌握。
- 一旦孩子产生新尝试，可见提示立即撤下，交互回到 0 级；历史最高级别保留用于依赖度记录。
- 同一根因的下一次挑战仍从 0 级开始，但可降低表面复杂度、改变材料或缩短初始观察窗口，不能继承成品提示。
- 禁止从一次错误直接跳到完整演示。

### 5.5 讲回与学科表达

讲回不是复述 AI 的话，而是用本学科认可的方式重新建立解释：

- 数学：对象、关系、步骤为何成立、如何检查；
- 文学：感受、具体词句、语境、解释之间的关系；
- 未来学科：由各自插件定义证据与表达规范。

### 5.6 无提示迁移

迁移任务应改变表面情境，保留待验证的深层结构。迁移阶段不继承本题的提示状态。

只有迁移成功，临时假设才有资格成为长期成长记录。经过 4 级演示、重建、讲回后在 0 级完成的迁移，允许写入长期记录，但记录必须携带“本次达成用过的最高提示级别”，对应的 `ScaffoldDependencyPoint.max_hint_level_used` 照常计入退出趋势。`assisted_round` 为真的迁移不能提交任何能力记录。迁移失败不宣布掌握，并进入软着陆：

- 先承认这是一次验证而不是考试，不把失败归因于孩子；
- 让孩子选择“换一个更简单的试试”“看看一个提示”“今天先到这里”；
- 任何后续辅助都明确标记为“不计入本次迁移验证”；
- 若继续学习，回到 `ASSESSING` 或新的低复杂度挑战；若结束，保存临时假设并安排日后重新验证。

### 5.7 跨轮退出指标

“AI 最终退出”必须跨轮、跨周可检验。系统为每个根因探针族和难度带记录 `ScaffoldDependencyPoint`：

- 达成讲回或迁移时用到的最高提示级别；
- 是否在 0 级完成无提示迁移；
- 首次产生有效表示所需时间；
- 是否发生主动自我修正；
- 挑战日期、探针族和难度带。

只比较同一探针族、相近难度带的挑战，禁止把更难任务造成的高提示级别误判为退步。连续至少三个可比挑战后，系统才生成趋势：

- 0 级迁移比例上升，或最高提示级别下降：脚手架正在退出；
- 最高提示级别持平：调整教学策略，不归因于孩子不努力；
- 最高提示级别上升：标记为教学警报，暂停增加难度并由家长审阅最近的介入历史。

该趋势是系统质量指标，不作为孩子可见的分数或排名。`ScaffoldDependencyPoint` 属系统自评，只含提示级别与时间，不含能力结论，因此来自所有会话而不限于孩子同意写入的记录；但它必须以中性、非排名的方式在孩子的“系统怎么理解我”视图中可见，例如“最近这些题，你自己做出来了几次”。作品被删除时其对应的 `ScaffoldDependencyPoint` 一并移除，趋势显示“数据不完整”而不静默重算。

## 6. 数学心智插件

### 6.1 数学家的心智循环

`猜想 → 建模 → 试验 → 论证 → 校验 → 迁移`

系统不以计算速度作为核心指标，而观察孩子能否把直觉变成模型，把模型变成可靠解释，并知道方法何时有效或失效。

### 6.2 五类根因假设

五类根因不是永久标签，而是可以被新证据确认、反驳或过期的诊断假设。

1. **数学表征断点**：没有把文字、数量和目标转换成正确的数学对象与关系。
2. **数学直觉断点**：会背规则，但缺少大小、方向、数量关系和原因的内部图景。
3. **策略工具断点**：拥有相关知识，却不会简化、分解、选工具或构造特殊案例。
4. **严谨链条断点**：总体方向正确，但条件、规则、计算、符号或解释中的某一步失效。
5. **校验反思断点**：缺少估算、逆向检查、替代方法、反例和讲回，错误无法自行暴露。

“粗心”不得作为根因。系统应继续定位严谨链条或校验习惯中的可行动断点。

五类根因不假设彼此正交。同一错误可以同时支持多个候选，但系统必须执行差异诊断：

- 同一轮最多维持三个活跃候选，分别保存支持与反驳证据；
- 不允许模型直接指定“唯一根因”；
- 下一验证任务必须能区分至少两个候选，即其中一种表现会支持 A、另一种表现会支持或保留 B；
- 优先选择信息增益高、对孩子干预最小的探针；
- 允许多个根因最终同时成立，但每次干预只选择一个主要目标，并保留次要候选；
- 被孩子异议的候选进入 `contested`，不能使用原证据重新确认。

例如 `2.4 × 0.3 = 7.2` 不能直接归类。可以依次使用区分性探针：

1. 计算前问结果应大于还是小于 `2.4`。若大小直觉错误，支持直觉断点；若直觉正确而算错，更支持严谨链条断点。
2. 给出错误结果后让孩子自行检查。若能用估算主动纠正，削弱校验断点；若知道结果应变小却没有检查，支持校验反思断点。
3. 换成不用小数点计算、但结构相同的表示任务，进一步区分表征与计算链条。

### 6.3 小数乘法完整切片

以 `2.4 × 0.3` 为示例，推荐流程如下：

1. 先问结果大概多大，不展示标准图；
2. 让孩子自己说出或画出 `0.3` 的意义；
3. 若卡住，先尝试更简单或相关案例；
4. 由孩子将 `0.3` 与十分之三、图形和算式连接；
5. 再进入精确计算和位值解释；
6. 要求孩子说明为什么结果小于 `2.4`；
7. 用 `×1.3`、新数字或新情境验证原有直觉的适用边界。

## 7. 文学心智插件

### 7.1 文学家的心智循环

`感受 → 细读 → 解释 → 辨析 → 修改 → 创造`

文学活动不寻找唯一标准感受，但要求解释尊重文本。成熟阅读既不能把文本当成事实问答材料，也不能把任意个人感受当作无需证据的答案。

### 7.2 第一版最薄切片

使用一段有合法来源的短文本，完成：

1. 孩子圈出最有感觉的一句；
2. 描述出现的画面、声音或情绪；
3. 指出哪些词句支持这种感受；
4. 比较另一种可能解释；
5. 修改原解释或保留分歧并说明理由；
6. 完成一段仿写；
7. 换一段文本，无提示发现相似写法。

这个切片只用于验证插件边界，不要求第一版覆盖完整语文课程。

## 8. 儿童互动设计

### 8.1 单屏原则

每轮只保留：

- 一个当前学习目标；
- 一句短问题或一个动作要求；
- 一个主要可操作区域；
- 必要的语音、画笔、圈选、撤销和拍题控件；
- 非教学性的“我在这里”呼吸指示灯；
- 常驻的“我卡住了”“我想休息”“你理解错了”入口。

孩子端不显示：

- Codex 原始聊天界面；
- 长篇聊天历史；
- JSON、工具调用和系统日志；
- 模型内部推理；
- 面向家长的能力分析和技术状态。

### 8.2 语音优先

- 支持孩子随时打断 Agent。
- 每次 Agent 发言尽量只包含一个教学动作。
- 长解释必须分成可交互的小段，每段都允许孩子回应。
- 转写被标记为 `unconfirmed` 或孩子主动纠正时必须请求确认，不能用未确认转写形成根因或长期记忆。

### 8.3 语义画布

画布不是截图集合，而是由带身份和学科含义的对象组成，例如：

- 自由笔迹、圈选、高亮、标签和箭头；
- 数轴、位值表、面积模型、竖式、几何图形；
- 文本片段、词句批注、意象连接、叙事时间线；
- 孩子层、Agent 层和原始材料层。

Agent 可以指向、高亮、补充和演示，但不能覆盖孩子原始笔迹。每次修改形成作品版本。

### 8.4 交互即证据

系统记录的不只是答案，还包括：

- 画了什么、先后顺序和修改历史；
- 圈选了哪个语义对象；
- 是否擦除、反复修改或改变策略；
- 口头猜想、解释和主动提问；
- 停顿时长，但不得把单次停顿机械解释为能力不足；
- 接受了哪一级提示；
- 能否在没有提示时重新构造。

### 8.5 孩子的异议权

“你理解错了”是画布上的一等交互元素，也支持自然语言触发，但不能只依赖语音识别。

触发后必须：

1. 立即停止当前诊断性追问；
2. 记录 `CONTEST` 事件并指向被质疑的假设或教学动作；
3. 将相关假设转为 `contested`，冻结长期写入和后续个性化使用；
4. 用儿童可理解的语言问“哪里和你的想法不一样？”，同时允许孩子选择跳过；
5. 若继续验证，生成新的区分性任务；原证据不得再次单独确认该假设；
6. 若需要家长参与，显示双方看到的原始作品和证据，不显示模型内部推理。

## 9. 成长记忆设计

### 9.1 四级数据链

`原始事件 → 本轮证据 → 临时假设 → 经验证的成长记录`

- 原始事件描述发生了什么；
- 本轮证据由学科插件赋予有限意义；
- 临时假设带证据引用、离散证据摘要、下一验证任务和失效时间；
- 长期成长记录必须包含无提示迁移结果。

第一版不保存由模型随口生成的浮点“置信度”。每个假设只保存可解释的离散事实：支持挑战数、反驳挑战数、不同表面情境数、无提示迁移成功数、提示后成功数和最近观察时间。未来只有在积累足够真实数据并完成校准后，才考虑引入统计置信度。

### 9.1.1 唯一写入者与分级门禁

只有运行在 Mac mini 上的 `GrowthLedgerService` 有权提交长期成长记录。Codex、学科插件、孩子端和家长端都不能直接改写账本；它们只能分别提出候选、提供规则、表达意愿或执行审阅。

写入分三档：

1. **原始作品和会话事件**：本地自动保存，受数据保留和删除策略约束，不包含能力结论。
2. **具体、可验证的任务能力**：无提示迁移通过、本地规则满足、孩子看过儿童版描述并选择“记下来”后，由 `GrowthLedgerService` 自动提交。家长无需逐条审批，但可以事后纠正或删除。
3. **跨轮习惯和趋势解释**：例如“开始主动校验”。必须至少来自三个可比挑战，先由家长审阅，再向孩子展示儿童版描述并取得同意，之后才能用于个性化教学。

任何门禁未满足时，候选停留在 `MEMORY_PENDING`，不得被后续挑战生成器当作已知事实使用。

### 9.2 需要长期积累的内容

- 孩子自己提出的问题；
- 独立构造的表示和模型；
- 创造或选择过的策略；
- 被证据修正的猜想；
- 数学讲回、阅读批注、作文及其版本；
- 正在形成的校验、引用证据、主动修改和承受暂时不会的习惯。

### 9.3 错题生命周期

`采集原过程 → 形成疑似根因 → 换题验证结构 → 最小干预 → 无提示迁移 → 毕业并低频回看`

做对原题不算毕业。只有在新情境中独立完成，才算掌握。

### 9.4 禁止标签

不得保存“粗心”“没天赋”“不擅长数学”“阅读理解差”等人格化、永久化判断。

每条能力判断必须具备：

- 具体对象和适用范围；
- 证据引用；
- 支持挑战数、反驳挑战数、不同表面情境数、无提示迁移成功数和提示后成功数；
- `suspected`、`confirmed`、`refuted`、`contested`、`expired` 或 `evidence_removed` 状态；
- 下一次验证条件；
- 孩子提出异议的记录。

### 9.5 孩子的知情与同意

- 首次使用时，用儿童可理解的方式说明系统会保存作品、学习过程和经过验证的成长记录，家长能看到哪些内容。
- 任何进入长期成长记录的结论，孩子必须在提交前看到儿童版描述和主要证据。
- 孩子可选择“记下来”“不确定”“不是这样”。三个选项不得设默认选中，“不确定”与“记下来”视觉等重。未选择“记下来”时，记录不能进入活动成长模型。成长模型为空时系统仍必须能跑完整闭环；连续拒绝只作为提示家长的信号，不作惩罚。
- 家长不能在孩子明确异议后静默启用同一结论；必须通过新的区分性证据解决异议。
- 孩子看到的每一句结论都由本地模板从学科插件提供的儿童版短语与离散计数渲染，家长与模型都没有改写它的入口；家长审阅只有批准、拒绝、收窄适用范围三个动作，收窄会重新渲染句子并作废原同意，重新征求孩子意见。
- 孩子随时可以查看“系统目前怎么理解我”，并对单条记录提出异议或请求删除。

### 9.6 三种视图

- **孩子视图**：我的问题、探索、作品、被我修正的猜想和新获得的方法。
- **家长视图**：独立程度、思维习惯、成长趋势和适合共同讨论的问题，不做分数排名。
- **Agent 视图**：细粒度证据、提示历史、临时假设、迁移结果和下一挑战候选。

### 9.7 权限矩阵

| 主体 | 原始作品/事件 | 临时假设 | 具体能力长期记录 | 跨轮习惯/趋势 | 删除与异议 |
|---|---|---|---|---|---|
| 孩子 | 创建、查看自己的内容 | 查看儿童版 | 提交前同意或拒绝 | 提交前同意或拒绝 | 可异议、请求删除 |
| 家长 | 查看、导出 | 查看证据摘要 | 可纠正、删除，无需逐条审批 | 必须事前审阅 | 可删除、发起复核 |
| Codex | 只接收最小必要上下文 | 只能提出候选 | 无写入权 | 无写入权 | 无权覆盖 |
| 学科插件 | 提供证据与迁移规则 | 提供证据的方向、来源探针与表面情境键 | 无写入权 | 无写入权 | 无权裁决异议 |
| `GrowthLedgerService` | 按保留策略落盘 | 保存状态转换 | 门禁通过后唯一提交者 | 双重门禁通过后唯一提交者 | 执行冻结、级联处理和审计 |

## 10. 核心概念契约

以下是逻辑契约，不限定具体编程语言或序列化形式。

### 10.1 LearningChallenge

- `discipline`：学科插件标识；
- `curriculum_anchor`：教材版本、章节或课程来源；
- `probe_family_id` 与 `difficulty_band`：用于生成区分性探针并进行可比的退出趋势分析；
- `development_goal`：要培养的学科心智；
- `learner_prompt`：儿童可见任务；
- `available_tools`：可用画布对象和实物工具；
- `independence_policy`：独立探索窗口与观察规则；
- `intervention_budget`：本挑战最多允许的升级次数和最高提示级别；上限由本地内核强制（软预算 2 次升级、硬预算 4 级），插件与 Codex 只能收紧；
- `expected_evidence`：本轮希望观察的证据；
- `hint_ladder`：逐级介入内容；
- `explain_back_spec`：讲回要求；
- `transfer_spec`：迁移任务生成和通过标准。

### 10.2 EvidenceEvent

- 客户端生成的全局唯一 `event_id`；
- `client_session_id`、设备标识和会话内单调递增的 `client_seq`；
- 服务端确认的 `last_confirmed_seq` 与接收时间；
- 事件内容哈希，用于识别相同 `event_id` 的冲突负载；
- `UTTERANCE`、`STROKE`、`SELECT`、`DRAG`、`ERASE`、`ANSWER`、`EXPLAIN`、`HELP_REQUEST`、`PAUSE_REQUEST`、`CONTEST`、`MEMORY_ASSENT` 等类型；
- 关联的语义对象；
- 原始值与确认状态；
- 识别结果的来源和离散质量状态，例如 `unconfirmed`、`confirmed`、`corrected`；
- 作品版本引用。

服务端以 `event_id` 建唯一约束；同一事件重放只返回原确认结果，不重复生成证据。若 `client_seq` 出现缺口，服务端要求客户端从 `last_confirmed_seq + 1` 重放。对高频笔迹点先在客户端聚合为一条语义笔画事件，再参与证据计数。

### 10.3 TeachingProposal

Codex 每一轮只向本地系统提出：

- `proposal_id`：用于拒绝、重试和防止重复播放；
- `spoken_response`：可被打断的语音内容；
- `canvas_actions`：语义画布动作；
- `learner_task`：一个儿童动作；
- `expected_evidence`：下一步观察目标；
- `hint_level`：建议提示级别；
- `memory_candidate`：可选的临时假设候选。

本地编排器必须验证提示级别、预算与升级门禁（新产出门禁、软/硬预算）、文本长度、学科合法性和画布动作后才能执行。

### 10.4 LearningHypothesis

- 目标能力或根因类型；
- `suspected`、`confirmed`、`refuted`、`contested`、`expired`、`evidence_removed` 状态；
- 正反证据引用；
- 支持挑战数、反驳挑战数、不同表面情境数、无提示迁移成功数、提示后成功数；
- 适用范围；
- 失效时间；
- 竞争假设与下一项区分性验证任务。

### 10.5 DisciplinePluginManifest

- 核心对象与表示；
- 思维动作；
- 证据规则；
- 学科提示模板；
- 作品类型；
- 根因探针；
- 讲回规则；
- 迁移生成器；
- 评价量规；
- 支持的课程映射版本。

### 10.6 ScaffoldDependencyPoint

- `hypothesis_or_goal_id`：对应根因假设或发展目标；
- `probe_family_id` 与 `difficulty_band`：限定可比范围；
- `max_hint_level_used` 与 `escalation_count`；
- `independent_transfer_succeeded`；
- `time_to_first_productive_action_ms`；
- `self_correction_observed`；
- 挑战与时间引用。

这个结构只用于判断教学脚手架是否正在退出，不进入儿童排名。

### 10.7 MemoryCommitDecision

- 候选记录和儿童版描述；
- 证据摘要与迁移引用；
- 写入档位；
- 本地规则校验结果；
- 孩子同意、异议或待定状态；
- 需要时的家长审阅结果；
- 本轮 `assisted_round` 状态：为真时拒绝提交第 2、3 档；
- 审计字段：决策者（`GrowthLedgerService`）、决策时间、依据的规则标识；
- 最终由 `GrowthLedgerService` 产生的提交或拒绝原因。

### 10.8 RealtimeBridge

桥接接口至少有三个实现，但只有一个 AI 模型实现：

- `CodexRealtimeBridge`：生产环境的唯一 AI 实时路径；
- `ScriptedReplayBridge`：读取固定脚本，模拟正常、越级、断线、转写错误等情况，用于确定性测试；
- `ParentCoachBridge`：家长手动输入短语音或画布动作，用于零代码教学验证和 Codex 不可用时的人工陪伴；家长每条输入必须标注提示级别，否则预算与 `ScaffoldDependencyPoint` 失真。

后两者不是第三方模型回退，不自主生成内容，也不能冒充 Codex 在线。三者必须输出同一个 `TeachingProposal` 契约。

## 11. 家庭部署架构

### 11.1 平板儿童端

平板只承担：

- 麦克风、扬声器和实时语音交互；
- 触控笔、语义画布和作品浏览；
- 拍题与本地文件选择；
- 家庭局域网中的会话连接。

平板不保存 Codex 长期凭据，不运行课程决策，不直接访问本地数据库。

第一版直接实现完整原生 iPad App，不使用 PWA、WebView、Capacitor 或 React Native。儿童端采用 `SwiftUI` 组织界面与状态，`PencilKit` 保存孩子原始笔迹，独立的 `SwiftUI Canvas/Core Graphics` 语义对象层显示数轴、分数条、箭头、高亮和 Agent 建议；Agent 层不得改写 PencilKit 笔迹层。实时音频使用 `AVAudioEngine`，本地打断必须在 iPad 内完成；与 Mac mini 的连接使用 `URLSessionWebSocketTask`。设备端只保留当前会话的可恢复缓存，不承担课程决策和长期成长记忆。

### 11.2 Mac mini Agent 宿主

Mac mini 运行：

- 儿童端本地 API 与 WebSocket 网关；
- 会话编排器；
- 学科插件运行时；
- 证据解释器；
- 作品服务与唯一长期写入者 `GrowthLedgerService`；
- 语义画布同步与版本服务；
- 课程映射服务；
- 家长视图；
- `RealtimeBridge` 及其 Codex、脚本回放和家长接管实现。

建议第一版本地存储使用 SQLite 保存结构化元数据，文件目录保存作品、图片和必要附件。数据库只保存文件引用，不把大对象塞进单一聊天记录。

### 11.3 Codex 桥接层

桥接层是唯一了解 Codex 实时协议的组件。它实现 `RealtimeBridge`，对内暴露稳定能力：

- 开始、停止和恢复实时会话；
- 追加音频、文字或确认后的语音片段；
- 接收转写、输出音频、状态和错误；
- 提交受约束的教学上下文；
- 将模型输出转换成 `TeachingProposal`；
- 屏蔽 Codex 具体事件名、字段和传输方式。

生产环境使用 `CodexRealtimeBridge`。开发、测试和家长先导试验使用 `ScriptedReplayBridge` 与 `ParentCoachBridge`；它们不调用其他模型，也不改变“Codex 是唯一 AI 模型路径”的决定。

本机已经从 Codex CLI `0.144.1` 生成 app-server schema，并确认存在：

- `thread/realtime/start`；
- `thread/realtime/appendAudio`；
- 转写增量与完成通知；
- 输出音频增量；
- WebSocket 与 WebRTC 传输定义。

本地证据位于：

- `work/codex-app-server-schema/ClientRequest.json`
- `work/codex-app-server-schema/ServerNotification.json`

2026-09-06 补注：以上是 `0.144.1` 时的快照。本机 Codex 已升至 `0.153.4`，其 `generate-json-schema` **不再导出任何** `thread/realtime/*` 请求定义（通知反而从 8 个增至 11 个，音频块 `ThreadRealtimeAudioChunk` 形状未变），因此 `work/` 下的旧快照只能作历史参考，不能当作当前契约证据；当前契约以阶段 0 计划 Task 7 Step 3 记录的实测比对与 `rust-v0.153.4` 源码为准，版本再变先重校。

这些接口属于实验性能力，当前不能等同于稳定公开产品契约。第一阶段必须先完成风险验证：

1. 当前 Codex 订阅身份是否可持续建立实时会话；**2026-09-06 实测：否。** codex-cli `0.153.4` 对 ChatGPT 登录身份拒绝 `thread/realtime/start`（`realtime conversation requires API key auth`），握手与 `listVoices` 可用但会话不可建立。第一版“订阅身份 + 不产生 API 计费”的前提在当前版本不成立，待用户裁决路线（见阶段 0 计划 Task 7）；
2. 是否产生额外 API 计费或存在使用限制；
3. 音频格式、延迟、打断和长会话稳定性；
4. app-server 特性开关和升级后的协议漂移；
5. Mac mini 到平板的音频中继路径是否满足体验。

若风险验证失败，第一版应停下报告，不得未经用户确认偷偷引入第三方模型。通用内核和本地数据设计不受影响。

### 11.3.1 实时体验预算

“跟手”和“可打断”必须用分段预算验收，不能只测总往返时间：

- 触控笔从采样到本机画布出现：P95 不超过 50 ms；
- 孩子开始说话到本机停止 Agent 播放：P95 不超过 200 ms，这一步必须在平板本地完成，不能等待 Codex 往返；
- 平板事件到 Mac mini 确认：家庭局域网 P95 不超过 150 ms；
- 孩子一句话结束到第一段 Agent 音频开始播放：P50 不超过 1.5 s，P95 不超过 3 s；
- 通过校验的远端语义画布动作在平板出现：P95 不超过 300 ms；
- 临时断线后自动恢复到最后确认状态：网络恢复后 5 s 内完成。

这些是第一版门禁预算，不是对 Codex 服务的既成承诺。零代码设备验证或 Codex 实时验证任一项持续超标，都必须先改变传输、缓冲或客户端方案，再进入主功能编码。

### 11.4 家庭网络

- 仅家庭局域网访问，不开放公网端口；
- Mac mini 上的 Codex app-server 仅监听回环地址；
- 平板只连接学习系统网关；家长视图与家长端接口只在学习主机本机可达（孩子端与 Mac 同在局域网，8.1 不允许孩子看到面向家长的能力分析与技术状态）；
- 阶段 0 和第一版家庭原型使用局域网 `HTTP + ws://`，不配置 TLS、配对和会话令牌；
- iPad 通过 Mac mini 的 `.local` 主机名连接学习系统网关，网关不得路由到公网；
- 这是用户明确接受的家庭单机简化边界；若未来开放公网、增加其他家庭成员或部署到非可信网络，再单独增加 HTTPS、配对和权限控制，不提前为该场景编码。

## 12. 本地数据与隐私

本地数据分为四类：

1. **课程库**：教材版本、章节、课程结构、材料来源和授权信息；
2. **作品库**：画布、笔迹、批注、讲回、作文版本、照片和附件；
3. **证据库**：会话事件、提示级别、策略变化、验证和迁移结果；
4. **成长模型**：可更新的能力假设、离散证据摘要、验证历史和到期任务。

默认长期保存：

- 语义笔迹和作品版本；
- 孩子确认后的关键文字转写；
- 教学动作和提示级别；
- 根因验证、迁移结果和证据引用。

默认不长期保存：

- 连续原始麦克风录音；
- 无关家庭环境声音；
- Codex 内部推理与工具日志；
- 未经验证的人格或能力判断。

家长应能导出、删除和纠正孩子的本地档案。删除作品时应明确关联证据与成长结论的处理方式，避免产生失去依据的孤立结论。

具体删除规则如下：

- 删除作品时级联删除只属于该作品、且没有其他用途的原始内容；
- 引用该作品的证据转为 `evidence_removed`，不再参与证据计数；
- 若长期记录失去其必需迁移证据，该记录立即转为 `evidence_removed`，停止用于个性化；
- 只保留不含作品内容的最小删除审计项，用于说明“某条结论为何失效”，不得保留被要求删除的文本、音频、图片或笔迹副本；
- 家长与孩子在删除前都能看到影响范围，避免误删整段成长历史。

事件与快照策略：

- 每次教学状态转换、每 100 条聚合事件或每 30 秒生成一次会话快照，以最先到达者为准；
- 高频触控采样在客户端聚合成语义笔画后再上传，原始采样点不进入长期事件表；
- 会话完成后保留最终快照、被证据引用的事件和作品版本；未被引用的临时交互事件默认保留 30 天后清理；
- 快照只有在其之前的事件已确认落盘后才可成为恢复点；
- 压缩与清理不得破坏 `event_id` 幂等审计和成长记录的证据引用。

## 13. 失败与恢复

### Codex 暂不可用

停止 AI 教学，明确告诉孩子当前无法继续；画布仍可使用和保存。不得伪装为正常，也不切换第三方模型。

### 实时语音中断

保存最后确认的会话状态、画布版本和已接收事件。重连后从最后确认点继续，避免重复播放或重复写入证据。

### 转写不确定

请求孩子确认。未确认的转写只能作为临时原始事件，不能触发根因判断和长期记忆。

### 模型输出不合规

本地校验器拒绝越级提示、长文本、无效语义对象、覆盖儿童笔迹或不允许的记忆写入，并要求 Codex 重述。儿童端只看到简短、自然的等待状态。

### 课程依据不足

若课程版本、题目来源或标准答案不明确，标记为待家长确认，不把模型生成内容伪装成教材事实。

### 服务重启

会话状态必须是可重放事件与明确快照的组合。Mac mini 重启后回到最后确认的教学状态，不依赖模型记住上下文。

## 14. 第一版范围与验收

### 14.1 数学完整切片

人教版五年级上册“小数乘法”应覆盖：

- 小数乘法意义；
- 结果大小和估算；
- 位值与小数点；
- 计算方法及其理由；
- 真实情境；
- 表面不同、结构相同的迁移任务。

不得把切片实现为固定题型分支或硬编码对话树。

### 14.2 文学最薄切片

文学插件应完成圈句、感受、文本证据、解释比较和短仿写。核心服务不得增加文学专用条件分支；差异必须来自插件契约。

### 14.3 一次真实会话必须发生

1. 孩子自然进入当前任务；
2. 在 AI 介入前独立产生表示、猜想或感受；
3. 笔迹、语音和修改形成可回放证据；
4. AI 根据证据单次最多提升一级，并遵守新产出门禁与单挑战提示预算；
5. 孩子重新取得控制权并形成学科解释；
6. 孩子完成无提示迁移；
7. 系统向孩子展示拟写入的成长描述，只有获得同意且门禁通过才写入；
8. 孩子能够通过常驻入口指出“你理解错了”，相关假设立即冻结并重新验证。

### 14.4 产品验收

- 语音可打断，笔迹跟手，画布与会话断线后可恢复；
- 每轮最多一个短问题，不显示聊天长文和系统内部信息；
- 每次提示都能追溯到证据和提示级别；
- 不允许从首次错误直接跳到完整演示；
- 每条长期结论都能追溯到作品、介入历史和迁移任务；
- 同一探针族、相近难度带积累至少三个挑战后，能展示最高提示级别和 0 级迁移比例的时间序列；若依赖持平或上升，系统把它标记为教学警报，而不是孩子失败；
- 任何长期记录在提交前都向孩子显示儿童版描述，并支持“记下来”“不确定”“不是这样”；
- 数学与文学插件通过同一套插件契约测试。

### 14.5 技术验收

- 课程档案、作品、证据和成长模型全部落在 Mac mini；
- 默认不保留连续原始录音；
- 平板不存在 Codex 长期凭据；
- Mac mini 服务重启后恢复最后确认状态；
- 非法画布动作、越级提示和未验证记忆会被本地规则拒绝；
- Codex 实时协议只存在于桥接层；
- 笔迹、打断、事件确认、首段音频和重连满足 11.3.1 的延迟预算；
- 文学插件接入时无需修改会话编排器、证据存储和成长记忆核心；
- 除插件注册表和测试夹具外，通用内核源码出现 `math`、`literature` 或具体学科标识符字面量即视为契约测试失败。

### 14.6 分阶段交付边界

保留“数学完整切片 + 文学薄验证”作为第一版 MVP，不把全部能力一次性编码：

1. **前置门禁**：家长白板扮演 Agent 跑完数学闭环；目标平板完成录音、播放、画线和家庭局域网 HTTP/WS 验证；Codex 完成实时订阅与延迟验证。
2. **单挑战机器原型**：只实现 `2.4 × 0.3` 一条主路径、`ParentCoachBridge`/`ScriptedReplayBridge`、本地画布和事件落盘；直接使用第 5.0 节完整状态表（同名状态、同一张表，部分转换暂不可达），不自造简化状态机；暂不生成长期假设，不承诺断线自动恢复。
   2026-09-06 实现状态：Mac 侧通用内核（5.0 完整状态表、提示预算、幂等事件日志、提案校验器、`RealtimeBridge` 接口）、数学插件薄切片、`ScriptedReplayBridge`/`ParentCoachBridge`、SQLite 落盘与家长控制台已实现，15.3 的八个脚本场景有确定性测试（见 `docs/superpowers/plans/2026-09-06-ai-scholar-phase-1-single-challenge-prototype.md`）；iPad 儿童端单屏会话界面（`apps/ipad/ScholarPad`：PencilKit 笔迹层、Agent 语义层、文字代替语音的说话入口、四个常驻按钮）已在模拟器跑通并有 UI 冒烟（见 `docs/superpowers/plans/2026-09-06-ai-scholar-phase-1-ipad-child-session-ui.md`），真机与 Pencil 待设备；断线暂停（`PAUSED_TECH`）、宿主重启从快照重建、儿童端重开续接同一会话已实现（`docs/superpowers/plans/2026-09-06-ai-scholar-phase-2-session-recovery.md`），阶段 2 原“不承诺断线自动恢复”的边界已提前满足；`CodexRealtimeBridge` 仍受阶段 0 门禁 BLOCKED 约束。
3. **数学 Alpha**：接入 Codex、完整状态机、提示预算、区分性根因探针、无提示迁移、分级成长写入，并含删除语义与跨轮退出趋势。后两项从阶段 4 提前，理由：删除要做到原子就必须与会话库同库同连接，晚做返工面更大；第 9.5 节“孩子可随时查看、异议、请求删除”的底线不能等；跨轮趋势是第 3 档写入的门禁输入，不做则第 3 档只能造假。代价是本阶段实现量与测试面约为原计划的 1.6 倍。
4. **双插件 MVP**：加入文学薄插件、家长视图完整形态和完整断线恢复。

每一阶段都有独立可用成果；前一阶段未通过，不进入后一阶段。第 18 节仍是第一版 MVP 的最终完成定义，不是单挑战原型的完成线。

## 15. 测试策略

### 15.1 确定性测试

- 第 5.0 节转换表中的全部合法转换，以及未列出转换全部被拒绝；
- 第 13 节每个失败场景都进入明确状态并可从确认点恢复；
- 提示逐级提升、单挑战预算、孩子新产出门禁、可见提示降级和新挑战归零；
- 迁移失败不得提交长期掌握记录；
- 未确认语音不得形成长期判断；
- 孩子笔迹层不可被 Agent 动作覆盖；
- 相同 `event_id` 重放不重复计证据，序号缺口从 `last_confirmed_seq + 1` 恢复；
- 离散证据摘要只能由已确认、未删除的事件计算；
- 孩子异议后相关假设冻结，原证据不能重新确认；
- 第 9.7 节权限矩阵中的允许和拒绝路径；
- 删除证据后的级联失效与最小审计项；
- Codex 提议超预算或违反新产出门禁被本地拒绝；
- `assisted_round` 为真时的迁移成功不得提交第 2、3 档记录；
- 暂停、求助、异议在任何活动状态都被接受。

### 15.2 插件契约测试

每个插件必须提供最小样例，验证：

- 挑战生成；
- 允许的语义对象；
- 证据解释；
- 提示阶梯；
- 讲回校验；
- 迁移任务；
- 作品保存；
- 不修改通用内核即可加载；
- 区分性探针能够对至少两个竞争假设产生不同证据；
- 通用内核不包含学科标识符硬编码。

### 15.3 模型行为测试

通过 `ScriptedReplayBridge` 使用固定会话脚本模拟：

- 孩子答错但仍在有效探索；
- 孩子沉默但正在画；
- 孩子主动求助；
- 语音转写错误；
- Codex 越级给答案；
- Codex 生成非法画布对象；
- 孩子反驳 Agent；
- 迁移任务失败和成功。

模型输出不可完全依赖提示词自觉，必须经过本地结构校验和状态机约束。

### 15.4 零代码家庭试用与设备门禁

写第一行业务代码之前，完成两项并行验证：

#### 教学闭环 Wizard-of-Oz

家长扮演 Agent，使用白板和口头对话，对孩子跑一次 `2.4 × 0.3` 完整闭环。家长严格按 0–4 级提示卡片操作，记录：

- 孩子最初如何理解任务；
- 30 秒探索窗口是否合适；
- 哪一句提示恢复了生产性；
- 孩子是否愿意讲回和做迁移；
- “我卡住了”“我想休息”“你理解错了”是否自然；
- 哪些证据真的能区分根因候选。

如果孩子明显抗拒这种学习方式，先修改第 5 章再编码。这次试用的真实话术、笔迹和观察记录将成为首批测试夹具，但未经家长与孩子同意不得进入开发样本库。

#### 原生 iPad 一次性验证 App

在实际目标 iPad 上用最小原生 App 验证 `PencilKit` 笔迹、`AVAudioEngine` 录音与播放、本地打断、`URLSessionWebSocketTask` 局域网明文 WebSocket 和断线重连，测量 11.3.1 的预算。验证 App 与正式儿童端使用同一原生技术栈，但不提前实现课程、成长记忆和完整语义画布。

### 15.5 机器版本家庭试用

机器原型完成后，先由家长使用 `ParentCoachBridge` 与 `ScriptedReplayBridge` 跑完脚本，再由孩子完成短会话。观察指标包括：

- 孩子是否无需解释界面就能开始；
- AI 是否打断思考；
- 提示是否真的帮助孩子重新生产，而不是只让他跟随；
- 孩子能否讲清楚并完成新情境迁移；
- 成长档案是否符合家长和孩子对本次过程的理解；
- 系统是否让孩子愿意继续探索，而不是只想尽快获得答案。

## 16. 主要风险与控制

### Codex 实时接口实验性

通过独立桥接层隔离，并把接口与订阅可用性验证设置为实现前置门槛。

### AI 过度脚手架

由本地状态机控制等待窗口、单挑战预算、降级规则和跨轮依赖趋势，不能仅依靠系统提示词。依赖不降反升时首先视为教学策略失败。

### 把行为误判为能力

区分原始事件、证据、假设和长期记录；使用离散证据计数而不是模型自报置信度；所有结论可反驳、可过期、可重新验证。

### 错误推断孩子情绪

第一版明确不做自动情绪识别。介入只使用孩子明确表达、常驻控件和任务进展；初始探索窗口采用 30 秒基线，早期使用时家长在附近可被主动呼叫。

### 孩子不知情或无法反驳

长期结论提交前必须向孩子展示并取得同意；“你理解错了”常驻可见，触发后冻结相关假设和个性化使用。

### 学科被通用流程稀释

学科插件拥有对象、证据、表达和迁移标准；通用内核没有最终内容裁决权。

### 课程与版权

教材只保存合法来源、必要映射和家庭已拥有材料的索引；模型生成内容必须标明来源类型，不冒充教材原文。

### 家庭隐私

默认本地保存、最小化上传、原始录音不长期保存、凭据留在 Mac mini，并提供家长导出和删除能力。

## 17. 后续实现顺序建议

正式实施计划应在本设计终审后单独编写。建议顺序为：

0. 家长白板 Wizard-of-Oz 教学验证；
1. 目标平板录音、播放、打断、触控笔和家庭局域网 HTTP/WS 验证；
2. Codex 实时能力、订阅路径和延迟风险验证；
3. 通用事件、显式状态机、`RealtimeBridge` 与插件契约；
4. `ScriptedReplayBridge`、`ParentCoachBridge` 和单挑战机器原型；
5. 平板单屏画布、Mac mini 同步和本地输出校验；
6. 数学小数乘法完整切片与 Codex 实时桥接；
7. 区分性假设、无提示迁移、分级写入和退出趋势；
8. 文学最薄插件；
9. 家长视图、删除语义、恢复测试和机器版本家庭试用。

## 18. 最终完成定义

第一版完成不是“平板能与 Codex 聊天”，而是：

> 一个真实孩子完成了一次独立探索闭环；系统用可追溯证据形成根因假设，按阶梯介入并最终退出；孩子在新情境中无提示迁移成功；经验证的成长被保存在 Mac mini；同一个内核又能运行一次文学细读活动。

- 增加客户端幂等键、序号确认和重放语义；

### 调整后接受

- 没有把已确认的第一版范围直接砍成单挑战演示，而是拆为零代码门禁、单挑战机器原型、数学 Alpha 和双插件 MVP。这样保留通用架构验收，同时避免一次性交付全部工程量。
- 没有要求家长逐条审批所有具体能力记录。具体、可验证的能力由本地规则、无提示迁移和孩子同意共同门禁；只有跨轮习惯与趋势解释需要家长事前审阅。
- 没有采用“语音总往返必须小于 700 ms”作为单一指标。打断必须在平板本地 200 ms 内生效；模型首段音频使用独立的 P50/P95 预算，因为两者是不同体验问题。

## 20. 仍需验证但不由文档猜测的问题

- 实际目标 iPad 型号及原生 App 是否满足音频、PencilKit、局域网明文 WebSocket 和恢复预算；
- Codex 订阅身份、是否额外计费、实验特性开关和长会话稳定性；
- 30 秒初始探索窗口是否适合这个孩子；
- 第一组区分性根因探针能否在真实互动中产生清晰证据。

这些是第 15.4 节和第 17 节的前置验证项。验证失败时修改设计或客户端方案，不允许由实现者凭感觉填空。
