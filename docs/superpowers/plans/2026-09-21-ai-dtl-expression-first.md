# 从孩子的表达出发 Implementation Plan

**Goal:** 执行用户确认的纠偏：不要“建模功能入口”，先自由说写画，AI 根据证据回应。

**Architecture:** 沿用 Swift 学习空间及现有千问语音连接。宿主在连接内保存有上限的孩子转写上下文，与题目版本绑定；只有明确教学授权才传给回复模型。不是新增持久成长判断，不给孩子贴标签。

**Tech Stack:** SwiftUI/PencilKit、TypeScript/Fastify、现有 Omni。

本会话串行执行，不委托、不提交、不推送。此前自主等分建模计划的常驻入口设计被用户本次纠正取代。

## 任务与验收

- [ ] 先改 `LearningWorkspaceUITests.swift`：新题断言无等分入口、仍可写画保存；不删除原来的图形底层单测。
- [ ] `LearningWorkspaceView.swift` 仅在已有图形时呈现“已有辅助图”，保留历史图形查看/编辑；新题没有工具诱导。
- [ ] 增加 `workspace-teaching-context.test.ts`：只取同题同题意版本最近 6 轮，每轮最多 1000 字；空转写不入上下文；新题不串旧题；JSON 内容仍是材料而不是指令。
- [ ] `workspace-voice-route.test.ts` 验证表达阶段没有调用 respond，授权后上下文包含孩子前面说过的话。
- [ ] `workspace-teaching-context.ts` 负责上下文边界与教学说明；route 在转写成功后加入记录。明确没有证据不声称看见、模糊先核对、具体证据与推测分开、不预设等分法、一次一步。
- [ ] 跑宿主相关测试和 typecheck；真机新题完整 UI 回归；重启已核实的本地宿主使新提示生效，启动正常 App。

明确边界：转写是可能有误的临时证据，不是孩子能力结论。断开连接清空临时表达；不假装已完成跨会话表达记忆、AI 生成图、或教师效果真人验收。保留现有异议过滤。提示词约束不是硬性证明模型永不偏题。

## 真实反馈促成的补充

第一轮真机五轮语音虽然通过旧 UI 断言，但审阅隔离测试会话 `bedf74f3-33f3-4df7-98ac-db5da913ce2f` 发现：澄清过长，且求助时未确认线段含义就提出等分，并连问两句。因此未把该测试成功作为教学合格证明。

增加保守的上下文规则：只有完整看得到上一条未被异议的教师问题和之后各轮表达，且孩子之后仅说完整匹配的求助/查看短语时，本轮求助只换一种方式问上一问，不自动升级提示。有实质新表达、已异议、窗口缺失均不推断“未回答”。这不是根因分类，也不保存能力标签。

强化真实语音验收：反馈从旧的 120 字上限收紧至原设计 60 字，最多一个问号；明确澄清不开始讲解法。仍不能声称流式模型输出有硬性语义保证。
